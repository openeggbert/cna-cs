# Native blockers for strict XNA behavior

Measured against the checked-out CNA C ABI headers and implementation on 2026-08-22. This file is
an implementation handoff, not permission to change the upstream `cna` repository. Microsoft XNA
4.0 source/IL and a future Windows runtime snapshot are authoritative; FNA and MonoGame results are
only differential evidence.

| Affected XNA API | Missing or defective native route | Observable CNA.NET behavior | Required upstream change | Safe managed fallback |
| --- | --- | --- | --- | --- |
| `GraphicsDevice.Present(Rectangle?, Rectangle?, IntPtr)` | `cna_graphics_device_present` accepts only the device. It cannot carry either rectangle or an override window. | The all-default argument tuple uses parameterless presentation. Any non-default argument throws `NotSupportedException` instead of silently presenting the wrong region/window. | Add a versioned presentation descriptor with independent optional source/destination rectangles and a pointer-width opaque override-window token, then implement clipping and override-target behavior for each backend. | Deterministic refusal for every non-default tuple. |
| `DynamicVertexBuffer.SetData(..., SetDataOptions)` | `CNA_VertexBufferTransfer.options` exists only on the built-in typed upload. `cna_vertex_buffer_set_data_raw` and `_raw_at` have no options field. | `None`, `Discard`, and `NoOverwrite` are forwarded for complete built-in typed vertices at offset zero. Non-`None` custom/raw, custom-stride, and offset uploads throw `NotSupportedException`. | Add `CNA_SetDataOptions` to a versioned raw/window upload descriptor and preserve Discard/NoOverwrite semantics through the renderer rather than treating them as aliases. | Forward only representable routes; never discard the option. |
| `DynamicIndexBuffer.SetData(offsetInBytes, ..., SetDataOptions)` | The transfer contains `options`, but the current `_set_data_at` implementation rejects non-`None` options. | Full-buffer `None`, `Discard`, and `NoOverwrite` uploads are forwarded. An offset upload with `Discard` or `NoOverwrite` throws `NotSupportedException`. | Implement optioned window updates in `cna_index_buffer_set_data_at`, including dynamic-only validation and renderer streaming semantics. | Full optioned updates work; unsupported optioned slices fail before native dispatch. |
| `VertexBuffer.SetData<T>` with an explicit stride that is not a complete declared vertex; `GetData<T>` with `sizeof(T) < vertexStride` | XNA uses `vertexStride` as spacing between `sizeof(T)`-byte copies, preserving/skipping gaps. CNA raw upload treats it as the complete source-vertex size and requires it to match the declaration; raw readback likewise copies complete `count * stride` bytes. | Declaration-sized uploads and contiguous full-byte windows work, including custom byte readback and model XNB byte arrays. Unrepresentable scatter/gather transfers throw `NotSupportedException` instead of zero-filling or overwriting XNA-preserved gaps. | Add scatter/gather descriptors with independent element size and buffer stride (plus buffer byte offset), preserving untouched bytes atomically. | Explicit refusal for partial/custom-stride scatter/gather; no zero-filled managed staging. |
| `Texture2D.SetData<T>` / `GetData<T>` for an arbitrary XNA-compatible struct | `CNA_TextureDataType` names a useful but closed set of 18 representations. XNA validates the actual element size against the surface format and can copy other blittable structs with a compatible layout. | Named types (`Color`, byte/ushort/float, vectors, and XNA packed-vector types) use typed native transfers. An untagged compatible struct such as `uint` is rejected rather than reinterpreted as another semantic type. | Add an untyped raw transfer carrying byte capacity, element size, mip/rectangle, and surface-format validation, with atomic readback. | No fake byte reinterpretation; unsupported element types throw `NotSupportedException`. |
| `GraphicsDevice.GetBackBufferData<T>` | Both backbuffer routes return only RGBA8 `CNA_Color`; they do not expose raw surface bytes or an element-size/format-aware copy. | `Color` works. Other element types throw `NotSupportedException` after managed array-window validation. | Add raw backbuffer readback plus active format and element-size validation equivalent to XNA's texture copy rules; retain atomic failure behavior. | Color-only readback, with explicit refusal for every other `T`. |
| `Texture3D.GetData<T>` | `cna_texture3d_get_data` reads `CNA_Color`; a raw upload exists, but no raw volume readback exists. | Raw generic upload is used where valid; readback supports only `Color`. | Add a raw mip-box readback with exact byte count, element-size/format validation, and no partial destination writes. | Color-only readback. |
| `TextureCube.SetData<T>` / `GetData<T>` | Per-face routes accept only `CNA_Color`; there is no raw/typed face upload or readback. | Only `Color` transfers work; other compatible element types throw `NotSupportedException`. | Add raw per-face/per-mip/per-rectangle upload and atomic readback with surface-format validation. | Color-only transfers. |
| `ContentManager.Load<SpriteFont>` for compressed atlases | The ABI has a byte texture tag, but the selected native backend rejects the checked DXT3 atlas upload used by the XNA font fixture. | The checked Color-atlas ownership fixture works. Loading the DXT3 font fixture fails explicitly; the corpus does not substitute decompressed/fake pixels. | Implement compressed DXT1/DXT3/DXT5 byte uploads consistently for texture creation/content loading on supported backends, or return a precisely documented format capability before resource construction. | The unsupported authored font is excluded from the native stress cycle and recorded as a backend limitation. |
| `GraphicsDevice.ResourceCreated` / `ResourceDestroyed` | The current callbacks correctly have three arguments `(device, info*, context)`. However, created info contains only `has_resource`; destroyed info contains name and only `has_tag`. No stable resource identity or round-trippable tag crosses the ABI. Native content paths can create resources without a managed facade constructor. | CNA.NET does not subscribe and emits zero fake events. The historical two-argument managed thunk would misread `info` as `context` and can crash on the first callback. | Supply a stable opaque resource identity that every direct and content-created resource can correlate with its eventual managed wrapper, and a round-trippable tag token on destruction. Define construction/destruction ordering and keep callback exceptions contained. A new versioned callback/info contract is preferable to changing the existing signature in place. | Store handlers safely but emit no event until the actual facade resource and tag can be supplied. |
| `DynamicVertexBuffer.ContentLost` / `DynamicIndexBuffer.ContentLost` | Both headers state that CNA currently never raises ContentLost. | Subscription lifetime is safe, but no native notification can be observed. | Raise the callbacks when renderer storage is lost/recreated, with defined ordering relative to device lost/reset events. | `IsContentLost` and handlers remain deterministic; no fabricated notification. |
| SpriteBatch invalid sort modes and non-finite draw values | The current native SpriteBatch route rejects some values before/during `End`; XNA `Begin` stores an unknown sort enum and XNA draw code propagates floating-point bit patterns. | Unknown sort mode and NaN/Infinity probes produce native `CnaException` outcomes; a failed `End` deliberately leaves the managed batch begun so state is not falsely reported as ended. | Align native validation and failure timing with XNA: preserve unknown-enum state until XNA's corresponding flush/sort path, and accept the same non-finite sprite values the XNA vertex path accepts. | Report the real failure and preserve recoverable managed Begin/End state. |

## Ownership/thread-affinity note

The current C API requires game-child destruction on the game owner thread. `NativeResourceHandle`
therefore queues finalizer and cross-thread releases, and `Game` drains/retries them at owner-thread
safe points and before game destruction. This closes the exercised game lifecycle, including a
failed parent release retried after its child. An upstream process-wide owner-thread pump would be
needed if future owned native handles can legitimately outlive every managed `Game` safe point;
the binding must not destroy those handles directly from the finalizer thread.
